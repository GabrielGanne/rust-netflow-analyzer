# AGENTS.md

NetFlow v5/v9 and IPFIX decoder and flow aggregator in Rust, with a C ABI.
Human-facing details live in `README.md`, `CONTRIBUTING.md`, and `docs/`.

## Repository map

- `core/` - `netflow_analyzer_core` crate (no `unsafe`)
  - `src/parser.rs` - packet/FlowSet/template parsing
  - `src/records.rs` - record decoding
  - `src/cache.rs`, `src/stats.rs`, `src/clock.rs`, `src/sampling.rs`, `src/scope.rs` - flow cache, aging, time, sampling, exporter scope
  - `tests/` - integration suites; `benches/` - Criterion; `examples/` - quickstart, UDP listener
- `ffi/` - `netflow_analyzer_ffi` C ABI crate; `include/netflow-analyzer.h` is generated by cbindgen
- `examples/c_integration/` - self-checking C/C++ ABI test
- `fuzz/` - cargo-fuzz targets and checked-in seeds (outside the workspace, pinned nightly)
- `tools/` - test, bench, fuzz, sanitize, audit, and symbol-check scripts
- `docs/` - architecture, aggregation, testing, hardening, exporter identity

## Test tools

- `./tools/test.sh` (`make check`) - full gate: fmt, debug/release/doc tests, clippy `-D warnings`, `cargo deny`, C example, exported symbols
- `cargo test` (`make test`) - quick Rust test run
- `make c-example` - C ABI integration test
- `./tools/bench.sh` - Criterion benchmarks with environment record
- `./tools/fuzz.sh [secs] [target]` - fuzzing (nightly + cargo-fuzz)
- `./tools/sanitize.sh [miri|address|thread]` - Miri and sanitizers (nightly)
- `RUSTDOCFLAGS="-D warnings" cargo doc --workspace --no-deps` - doc build

## C ABI invariants

- After changing types in `ffi/src/lib.rs`, run `make header` and commit the regenerated header.
- Add struct fields by consuming `reserved` slots and bumping `NETFLOW_ANALYZER_ABI_VERSION`.
- Keep `examples/c_integration/abi_checks.c` and `tools/check_symbols.sh` in sync.
- Update `CHANGELOG.md` under `[Unreleased]` for user-facing changes.

## MCP Tools: code-review-graph

**When the code-review-graph MCP tools are available, use them BEFORE
Grep/Glob/Read to explore the codebase.** The graph gives structural context
(callers, dependents, test coverage) that file scanning cannot. Fall back to
Grep/Glob/Read only when the graph doesn't cover what you need.

| Tool | Use when |
| ------ | ---------- |
| `detect_changes` | Reviewing code changes - gives risk-scored analysis |
| `get_review_context` | Need source snippets for review - token-efficient |
| `get_impact_radius` | Understanding blast radius of a change |
| `get_affected_flows` | Finding which execution paths are impacted |
| `query_graph` | Tracing callers, callees, imports, tests, dependencies |
| `semantic_search_nodes` | Finding functions/types by name or keyword |
| `get_architecture_overview` | Understanding high-level codebase structure |
| `refactor_tool` | Planning renames, finding dead code |

The graph lives in the git-ignored `.code-review-graph/` directory; refresh it
with `build_or_update_graph_tool` when it is stale. One-time setup per machine
(the MCP registration holds machine-specific paths and is not committed):

```sh
pipx install code-review-graph
code-review-graph install --repo .
code-review-graph build --repo .   # then `update` for incremental refreshes
```
